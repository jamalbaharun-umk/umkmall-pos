# UMK-1987 and UMK-1973: WhatsApp receipt and kasbon reminder

Design features 33 "Struk digital lewat WhatsApp" and 34 "Pengingat kasbon lewat WhatsApp" (both approved).
Epic UMK-1924. Replaces features 12 and 13.

## Goal

After a sale the cashier offers the receipt on WhatsApp; from the Piutang list or a customer's kasbon the owner (or staff
holding `receivables.manage`) sends a polite reminder. Both open `https://wa.me/62...?text=...` with the message ready;
the person presses send in WhatsApp. No WhatsApp API: the POS never claims a message was sent.

## Decisions

- **No new table.** The design stores "the date of the last reminder on the customer's data, without the message": one
  nullable column on `pos.members` (already RLS, `tenant_id`, purged with the tenant). No reminder log.
- **Phone from the member record only.** The receipt answer adds `memberPhone` (read in `receipt()`, not in `get()`, so the
  sale detail and the agent never carry it). A typed number is never stored; the reminder answer carries the stored number
  only to the signed-in actor with `receivables.manage`, and its routes are not `@AgentRoute`.
- **Messages are built in the browser from the server's figures** (receipt, reminder amounts); nothing is recomputed.
  Normalisation is browser-side because it runs on every keystroke; the server stores whatever `Phone` already accepted.
- **Reminders count per customer, not per sale:** the amount is every open kasbon of the customer, the date the oldest due.
- **Marking happens on "Buka WhatsApp"**, after the window opens inside the press (a popup blocker allows only that); it
  means "offered", not "sent". A failed save still leaves WhatsApp open and says so.
- **Receipt number is plain** (`#144`), like every other screen, not the design's zero-padded `#0144`.
- **Queue for "Kirim pengingat ke yang terlambat":** WhatsApp opens one chat per press, so it walks the late customers
  with a number one dialog at a time (at most 50, oldest first).
- **Rounding in the receipt message:** with cash rounding the message reads `Total`, `Pembulatan`, then
  `Harus dibayar <amountDue> (tunai)`, the server's `total + rounding`; without rounding, `Total ... (tunai)`.
- **Deleted customers** are not reminded: the read and the mark answer 404, they are out of the late queue, and the list
  hides their button (`memberDeleted`).
- **Queue:** "Lewati" skips a customer; a customer that cannot be loaded, has no number or owes nothing skips
  itself, so one bad customer never ends the queue.
- **The "reminded under 3 days ago" question is only a warning**, and there is no server rate limit: nothing is sent
  automatically, the owner presses send in WhatsApp every time.
- **Buttons (guideline v2):** one line, three words at most, 44 px, always in an `ActionRow` (the per-row reminder
  button, "Salin pesan", "Ingatkan yang terlambat"); the paid dialog's three buttons are a column at every width.
- Not audited: the design lists no audit event for either feature.
