## OPEN items: status

1. **FIXED in 1b57d08** (ui-parity-b): a "Diskon" field in the order panel, shown only with
   `sales.price_override`, sends the order `discount` (whole rupiah, ≤ subtotal, field errors). Browser: Rp3.465 case
   above; a cashier without the permission sees no Diskon row. The discount is per order (what pos-api accepts); a
   per-item discount would need a server change.
2. **Error pages answer HTTP 500** for 403 and API-down states (shared shell `PageError`). HANDED OVER to
   ui-parity-a. The page text is right; the status is not. Recommendation: set the response status from the error
   (403/503) in the root error handling.
3. **No pagination on members and receivables.** FIXED. `GET /members` and `GET /receivables` take `page` and
   `perPage` like `/sales` (default 20, at most 100) and answer `{ data, total, page, perPage }`. Members search
   name/code/phone; receivables search the member name or a sale number ("12" / "#12") and carry the outstanding
   summary over the whole search, independent of page and tab. The screens show "Menampilkan X–Y dari Z" with
   `@umkmall/ui` Pagination; the capped-list notices are gone. Tests: `test/members-paging.e2e-spec.ts` (page
   boundaries incl. past the last page, perPage 0/101 and page 0/"abc" refused with field messages, search by
   name/code/phone/sale number, LIKE wildcards literal, summary unaffected by page and tab, cross-tenant by list,
   search and sale number); revert-red once (offset removed → red, restored → green). Browser: g01–g06.
4. **FIXED in 1b57d08**: after a kasbon the success dialog shows "Sisa kasbon: RpX" from `receivableRest`
   (browser: Nasi Goreng Rp24.200, down payment Rp4.200 → "Sisa kasbon: Rp20.000").
